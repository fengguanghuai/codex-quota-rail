# Codex Quota Rail 首次安装与回归

目标是用户从原来的 Codex 图标打开后，侧栏出现真实额度。Skill 负责一次性适配和验收；运行时由后台助手完成，不需要 AI 常驻。

## 定位版本和环境

- 从用户给出的源码目录或解压目录定位根目录，确认 package.json 的 name 是 codex-quota-rail，并有 src/cli.mjs。单独安装本 Skill 时不假定当前目录就是仓库；缺少安装来源时询问用户，或读取用户指定的 GitHub 仓库。
- 先读该版本 README.zh-CN.md、package.json 和相关平台实现，以实际版本为准。不要借用另一个分支的路径、参数或旧安装流程。
- Mac 原生监听助手当前需要 macOS 14+，Node.js 22+，客户端已登录。读取系统与 Node 版本、运行状态，执行 node src/cli.mjs status；检查原生助手存在且架构兼容。发布 ZIP 包含原生助手，普通用户不需要 Xcode。
- 用户要求首次回归时先记录实际基线。已经安装就如实说明，不能假称干净首次安装；卸载现有健康安装须符合当前用户授权。
- Windows 不自动按此流程安装或创建快捷方式，参考该版本 Windows 文档并报告验收范围。

## 安装

1. 复用健康安装，除非任务明确要求重装或首次回归。检查 /Applications 和 ~/Applications 中的 Codex.app、ChatGPT.app；安装器会校验应用内置 CLI。多份有效客户端且常用目标不明确时，询问一次目标，不凭账户信息猜测。
2. 改名或自定义路径用 CODEX_QUOTA_APP 指定绝对 .app 路径，执行 node src/cli.mjs install。路径包含空格时正确引用，不拼接用户输入为 shell 代码。路径保存到本地 settings.json，后续自启无需再次设置环境变量。已保存路径失效时显式指定新路径重装，不静默切换应用或使用另一份全局 CLI。
3. 安装后复查 status 的 installed、appPath 和后台状态。不要直接读取认证文件或输出原始账户 RPC；诊断只记录状态、版本、时间和必要路径。
4. 不改 Codex 应用包、签名、原图标或 Dock，不创建另一个“额度版”图标。后台随登录启动，通过系统事件识别原图标启动。原安装目录为当前用户 Library/Application Support/CodexQuotaRail。
5. 不因安装就退出正在运行的 Codex。首次启用需要完全退出再打开时，先明确告知会关闭当前客户端，并让用户保存工作；当前回归会话也在 Codex 内时，应让用户手动完成这一步。已有明确且适用的重启授权无需重复询问，但必须保留回归续接信息。

## 原图标回归

安装前若客户端本来就带调试参数，安装后立即显示只能证明注入成功，不能证明原图标启动成功。

- 用户保存工作后按 ⌘Q 完全退出，然后点击原来的应用图标。当前版本使用系统事件，不再要求等 5 秒；启动时先不要输入或点击，让受保护的重开完成。
- 正常行为：新进程位于前台、完成初始化且没有新输入时，助手可能正常退出并重开一次。已经开始操作时跳过重开是保护生效，不应通过强杀、循环重试或取消保护来让测试通过。
- 回到会话后确认本地连接有效且监听者是目标客户端；status 的 checkedAt / lastSync 新鲜、state=ready、attachedWindows>=1、startup=listening。
- 使用可用的界面检查工具验证头像上方圆环与详情，或由用户明确确认。截图只取组件区域，避免公开聊天和账户信息。
- 验证悬浮详情、点击固定、关闭、中英文切换和标题套餐。没有 5 小时窗口、重置卡或额外点数的数据不能伪造补齐。
- 做一次完整退出后从原图标重开的验证；若同一退出已满足此项，不重复打断用户。登录自启、整机重启和其他 Mac/账户兼容性属于独立覆盖项，未测试就注明。

## 异常与停止条件

- startup=unavailable：检查原生助手启动、系统版本/架构、系统拦截；不关闭系统安全防护。
- waiting-for-client：检查助手是否比客户端晚启动、启动后是否已有输入、端口或客户端路径是否错误；不要立即宣称客户端不兼容。
- connectionAvailable=true 但时间陈旧：检查后台进程和安装目录；attachedWindows=0 则检查侧栏锚点兼容性。
- 一次原图标重开未成功，保留证据并定位原因，不要求反复盲目重启。Start Codex.command 可在完全退出后作为备用诊断入口；其成功不等于原图标验收成功。
- 用户请求代码修复时再进行必要修复和对应测试；安装回归本身不授权推送、发布、合并 PR 或改变系统级配置。

## 卸载与报告

用当前版本 node src/cli.mjs uninstall，复查安装目录和 LaunchAgent 已移除。保留用户下载目录、Codex、登录和会话。剩余调试端口需完全退出客户端，再从原图标打开才能关闭。

报告版本、实际入口、已验证项、未覆盖项和下一步。区分“安装完成”“连接成功”“实际界面显示”“原图标重开成功”“登录/整机重启验证”，不要只用一个“通过”概括。跨会话重启前先将这些信息保存在用户任务的输出目录，便于续接。
